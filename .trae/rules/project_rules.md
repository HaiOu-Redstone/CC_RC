# CC\_RC 项目规则

## 开发日志（必须维护）

- 开发日志固定保存在项目根目录：`DEVELOPMENT_LOG.md`。
- 日志分三部分：`一、目录`（索引）、`二、代码`、`三、注册物品`。
- **注册新物品/方块时**：必须在同一轮改动中同步更新日志，规则如下：
  1. 在「一、目录」索引表中新增对应行（如新增方块/物品/功能分类）。
  2. 若涉及新逻辑，在「二、代码」补充对应章节与关键代码示例。
  3. 在「三、注册物品」按方块类归属添加条目，并同步更新各节统计数量（方块/物品/方块实体/声音总数）。
- 修改/删除已有注册内容时：同样必须同步更新日志对应条目与数量。
- 新增音乐唱片时：需同时更新「三、注册物品 → 2. 物品 → 音乐唱片表」与「三、注册物品 → 4. 声音」两张表，并同步更新「三、注册物品」开头的物品总数统计。
- **调用以前写过的代码时**：先通过日志「一、目录」索引或「三、注册物品」表格查找对应方块/物品的类名与文件路径，再定位源码，避免重复造轮子。

## 代码注释（必须遵守）

- **写新代码时必须添加注释**：新增/修改的类、方法、关键逻辑需附中文注释，说明其用途与实现要点。
- 注释须与代码真实行为一致；修改逻辑时同步更新受影响注释，禁止残留过时/误导性注释。
- 修改他人或旧代码时，对理解有歧义处可补充注释，但不得改动他人明确保留的原意。

## 构建与校验

- 修改 Java 源码后，在项目根目录运行 `gradlew build` 验证编译。
- 修改资源（贴图/模型/blockstate/sound）后，检查对应 JSON 引用是否成对，避免残留未使用文件。
